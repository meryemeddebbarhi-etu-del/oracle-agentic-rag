Oracle 19c : installation sous Linux, outils d'accès et création d'une base de données

1. Installer Oracle Database 19c sous Oracle Linux

Le guide d'installation travaille avec Oracle Database 19c installé sur Oracle Linux 7. Après l'installation du système (partitionnement, fuseau horaire, mot de passe root, réseau, nom d'hôte), on met d'abord à jour le serveur avec yum update et yum upgrade. L'installation de la base se fait ensuite en plusieurs étapes.

Étape 1 : mettre à jour le fichier /etc/hosts en y ajoutant l'adresse IP, le nom d'hôte et le nom de domaine complet (FQDN) du serveur.
Étape 2 : installer les paquets prérequis avec yum install (bc, binutils, compat-libcap1, compat-libstdc++-33, elfutils-libelf, glibc, ksh, libaio, libaio-devel, libXrender, etc.).
Étape 3 : créer les groupes système : oinstall (propriétaire de l'installation), dba, oper, backupdba, dgdba, kmdba, asmdba, asmoper, asmadmin et racdba, avec la commande groupadd.
Étape 4 : créer l'utilisateur oracle, utilisé pour installer et gérer la base, et l'ajouter à ces groupes : useradd -u 54321 -g oinstall -G dba,oper,backupdba,dgdba,kmdba,asmdba,asmoper,asmadmin,racdba oracle. L'utilisateur root ne sert qu'à administrer le serveur, alors que l'utilisateur oracle administre la base.
Étape 5 : régler SELinux en mode permissif (SELINUX=permissive dans /etc/selinux/config, puis setenforce Permissive).
Étape 6 : désactiver le pare-feu (systemctl stop firewalld et systemctl disable firewalld).
Étape 7 : créer les répertoires. Oracle a besoin de deux chemins : ORACLE_BASE, le dépôt de tout ce qui concerne Oracle, et ORACLE_HOME, qui contient les binaires et la configuration du logiciel. Exemple : mkdir -p /u01/app/oracle/product/19c/db_1 et mkdir -p /u01/oradata, puis chown -R oracle:oinstall /u01 et chmod -R 775 /u01.
Étape 8 : éditer le fichier .bash_profile de l'utilisateur oracle pour définir les variables d'environnement : ORACLE_HOSTNAME, ORACLE_UNQNAME=orcl, ORACLE_BASE=/u01/app/oracle, ORACLE_HOME=$ORACLE_BASE/product/19c/db_1, ORACLE_SID=orcl, PDB_NAME=pdorcl, DATA_DIR=/u01/oradata, et PATH pour inclure $ORACLE_HOME/bin.
Étape 9 : télécharger le logiciel, le décompresser dans ORACLE_HOME avec l'utilisateur oracle (pas root), puis lancer l'installateur avec ./runInstaller.
Étape 10 : résoudre les erreurs d'affichage. Sur un serveur sans interface graphique, on se connecte en SSH depuis une machine disposant d'une interface graphique et de Java (par exemple avec MobaXterm), et on renseigne la variable DISPLAY dans le .bash_profile.
Étape 11 : suivre l'assistant d'installation : choisir « créer et configurer une base de données mono-instance », la classe serveur (server class, par opposition à desktop class pour un portable), l'édition Enterprise (d'après le guide, l'édition Standard ne permet de créer qu'un seul conteneur de base de données, alors que l'édition Enterprise permet d'en créer autant que nécessaire et offre davantage de haute disponibilité et de sécurité), confirmer ORACLE_BASE, le répertoire d'inventaire et le groupe oinstall, le nom de la base globale, la mémoire, le jeu de caractères, l'emplacement des fichiers, puis exécuter les scripts root demandés.

2. Se connecter après l'installation

Pour se connecter à Oracle avec l'utilisateur oracle du système : sqlplus / as sysdba (authentification système), puis show user doit afficher SYS. Après un redémarrage du serveur, la base ne redémarre pas automatiquement : il faut d'abord démarrer le listener avec lsnrctl start, puis lancer STARTUP dans SQL*Plus. Quand le message « Database opened » s'affiche, la base est en ligne. Pour SQL Developer, il faut installer le JDK Java, extraire l'archive et lancer sqldeveloper.exe, puis créer une connexion avec le signe +.

3. Se connecter à une instance Oracle

On connecte les applications clientes à l'instance de la base. Une session utilisateur est l'entité logique qui représente l'état de la connexion courante. Exemples : l'authentification par le système d'exploitation avec sqlplus / as sysdba, ou la syntaxe de connexion simplifiée Easy Connect : CONNECT hr/hr@host1.example.com:1521/db.example.com. On peut aussi exécuter un script depuis la ligne de commande : sqlplus hr/hr@HRPDB @script.sql.

4. Les outils d'administration d'Oracle Database

Chaque outil Oracle a son propre usage, et certaines opérations peuvent être faites dans plusieurs outils ; le choix dépend souvent des préférences. Les outils sont : SQL*Plus (ligne de commande), SQL Developer (interface graphique, avec le navigateur DBA), SQLcl (ligne de commande moderne), DBCA (Database Configuration Assistant), Oracle Enterprise Manager Database Express (EM Express), Oracle Enterprise Manager Cloud Control, ainsi que Listener Control, Net Configuration Assistant, Net Manager, ADRCI, SQL*Loader et Oracle Data Pump (export et import).

5. Créer une base de données avec DBCA

DBCA (Database Configuration Assistant) est l'outil de création et de configuration d'une base Oracle. Il a deux modes : interactif (interface graphique et assistant guidé) et non interactif ou silencieux (arguments en ligne de commande, fichier de réponses, ou les deux). Il peut être lancé par l'installateur Oracle Universal Installer ou après l'installation du logiciel. Il permet de créer une base, de gérer des modèles de conception de bases, de supprimer une base, de gérer les PDB (créer, supprimer, déconnecter) et de modifier la configuration, et il peut générer les scripts de création.

Avant de créer la base, le DBA doit planifier la structure de stockage logique et physique : quel type de stockage, combien de fichiers de données (prévoir la croissance), combien de tablespaces, quels types d'informations, quelle stratégie de sauvegarde. DBCA propose des modèles : usage général ou transactionnel (OLTP, par exemple facturation), entrepôt de données (data warehouse) ou modèle personnalisé.

Exemple de commande silencieuse, qui crée une CDB ORCL avec une PDB : dbca -silent -createDatabase -templateName General_Purpose.dbc -gdbname ORCL -sid ORCL -createAsContainerDatabase true -numberOfPDBs 1 -pdbName pdb1 -useLocalUndoForPDBs true -characterSet AL32UTF8 -totalMemory 1800 -emConfiguration DBEXPRESS -emExpressPort 5500 -enableArchive true. Pour supprimer la base : dbca -silent -deleteDatabase -sourceDB ORCL -sid ORCL.

6. Le choix du jeu de caractères

Le jeu de caractères est choisi à la création de la base. Il faut choisir celui qui répond aux besoins actuels et futurs, car il est difficile de le modifier ensuite. Oracle prend en charge les jeux monooctets (7 bits, 8 bits) et multioctets, dont Unicode. Unicode (AL32UTF8) est recommandé car c'est le plus souple. La variable NLS_LANG du client doit être correctement réglée : Oracle Net compare NLS_LANG avec le jeu de caractères du serveur et convertit automatiquement si nécessaire. Un NLS_LANG incorrect peut faire entrer des données invalides dans la base.

7. Créer une CDB avec la commande SQL CREATE DATABASE

On peut créer une base conteneur manuellement : 1) définir ORACLE_SID=CDB1 et créer le fichier de paramètres initCDB1.ora avec CONTROL_FILES, DB_NAME et ENABLE_PLUGGABLE_DATABASE=TRUE ; 2) démarrer l'instance avec CONNECT / AS SYSDBA puis STARTUP NOMOUNT ; 3) exécuter CREATE DATABASE cdb1 ENABLE PLUGGABLE DATABASE avec les clauses USER SYS IDENTIFIED BY, USER SYSTEM IDENTIFIED BY, LOGFILE GROUP, CHARACTER SET AL32UTF8, EXTENT MANAGEMENT LOCAL, DATAFILE pour SYSTEM, SYSAUX DATAFILE, DEFAULT TEMPORARY TABLESPACE, UNDO TABLESPACE et SEED FILE_NAME_CONVERT ; 4) exécuter ensuite les scripts catcdb.sql (qui lance catalog.sql et catproc.sql) depuis la root.

La clause ENABLE PLUGGABLE DATABASE rend la base conteneur et crée CDB$ROOT et PDB$SEED. Sans SEED FILE_NAME_CONVERT, on utilise OMF (paramètre DB_CREATE_FILE_DEST) ou le paramètre PDB_FILE_NAME_CONVERT pour indiquer où placer les fichiers de la PDB seed.
